# 修复本地PDF快速探针准确性

## Goal

修复数字 PDF 的本地快速探针因 PDF 内部对象顺序而导致的金额、铁路行程方向和购买方信息不准确，确保低置信结果回退至现有 OCR 提供商。

## Confirmed Facts

- `fast_probe.extract_pdf_embedded_text()` 目前按 PyMuPDF 默认对象顺序提取文本。
- 已定位样票 `26337000000698760199.pdf` 的本地金额为 5.83，视觉排序文本可得 6.00。
- 已定位样票 `26339190041007967535.pdf` 的本地铁路路线被反向，视觉排序文本可恢复杭州东站至福州南站。
- 现有快速探针成功后会跳过 OCR；测试目前只校验字段非空，未锁定上述真实票面字段。

## Requirements

- 本地 PyMuPDF 文本提取使用视觉阅读顺序，且保留现有 pypdf 降级行为。
- 本地金额提取不得因命中第一个金额候选而错误返回明细金额；金额比较保持 `Decimal` 精度。
- 高铁探针应提取排序后文本中的起点、终点、出行日期和清洗后的购买方名称。
- 本地解析结果缺少该票种的关键字段时，不得静默作为成功结果，应继续使用既有 OCR 路径。
- 为已定位的地铁和高铁 PDF 添加精确、离线、可重复的回归测试。

## Acceptance Criteria

- [ ] 地铁样票 `26337000000698760199.pdf` 本地探针金额为 `6.00`。
- [ ] 高铁样票 `26339190041007967535.pdf` 本地探针路线为 `杭州东站` 至 `福州南站`，出行日期为 `2026-07-14`，购买方为 `杭州勤合能源科技有限公司`。
- [ ] 缺少票种关键字段的本地探针结果会进入既有 OCR 回退路径。
- [ ] 新增测试包含上述精确断言，且相关快速探针和流水线测试通过。

## Out of Scope

- 不更换 OCR 服务商或修改云端 OCR 配置。
- 不重构其他未提交的报销、行程或 HTML 导出功能。
- 不追求所有 PDF 版式的完全字段等价；未知版式由既有 OCR 回退处理。
